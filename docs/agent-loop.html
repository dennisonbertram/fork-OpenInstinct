OpenInstinct Agent Loop

How one user message becomes one reply. Every box names the file that owns it. eve runs the loop as a durable workflow; the project supplies the channels, hooks, tools, skills, and instructions around it.

Hooks that fire during the loop

event what runs
session.started ensureScope, claimSession. agent/hooks/session-owner.ts
message.received saveChat. agent/hooks/session-owner.ts
turn.started checkBudget on model tokens; a blown budget fails the turn before the model runs
step.started check auth and lease, then pick the workspace gateway model; model-free contract evals select their local fixture. agent/agent.ts
step.completed recordUsageEvent with tokens and cost estimate
input.requested Linq: persist workspace-bound request IDs, then post generic plain-text choices; a clear natural confirmation or cancellation becomes Eve's structured input response. agent/channels/linq.ts
message.completed Linq: typing status or bubble posting. agent/channels/linq.ts
turn.started / input.requested / failed / cancelled scheduled runs only: lease and report lifecycle. agent/hooks/scheduled-run-completion.ts
every event evlog, redacted, message bodies omitted. agent/hooks/evlog.ts

Things the pictures do not show

  • Memory has its own lifecycle. Providers capture before compaction and recall after, so a summary never loses the profile. Two providers: agent/memory/profile.ts (file memory, Vercel Blob in production) and personal_info.
  • The root has no browser tools. Browser work is delegated with a Task line and an output schema; the browser-agent's 16 tool modules live under its own directory and are invisible to the root. The worker uses an image-capable model to inspect screenshots. Snapshots and element searches provide opaque target tokens for actionable controls, bound to the exact observed frame and label. Dropdown options do not crowd form controls out of the bounded list. The worker is instructed to complete non-secret fields before vault injection and observe the final submit control before filling secrets. It is instructed to start login assignments with a profile writer and verify a specific postcondition after committing. Vault-filled pages expose only safe text verification status, while masked image capture remains available in the same browser. Explicit signup autofill fills the saved password and confirmation in the focused registration form; ordinary login autofill still excludes new-password fields. An explicit compatibility flag accepts a mislabeled sole password only in a focused sign-in form with an unambiguous Login/Sign in control; registration, reset/change, OTP, and multiple-password forms remain excluded. Registration is verified and captured before closing the writer. A following login form uses a fresh profile writer to observe its own targets. Text-bearing evidence starts at a 320px viewport (up to 360px when needed) and uses a focused crop for phone chat.
  • A scheduled run is its own channel and turn. agent/schedules/dynamic.ts is a once-a-minute cron that claims due jobs and dispatches them onto agent/channels/scheduled-run.ts; agent/hooks/scheduled-run-completion.ts tracks the lease, waits for input, and reports back on completion/failure/cancellation. A cron turn has no initiator, so it cannot use the per-user Square grant. That is the open constraint on proactive checks (issue #34).
  • Web chat and iMessage share one agent. Different channel files, same instructions, tools, and scope derivation. Only the delivery step differs. A message marked final: true closes messaging for that turn; Linq first waits for provider acceptance and treats a failed send as unconfirmed. Later sends after confirmed completion are rejected and the next step omits messaging tools. Web chat keeps its session observer open while waiting and retires delivered or cancelled worker observers; worker approvals appear in the normal conversation without requiring the developer trace. Parent completion receipts also settle the task sidebar, without polling or opening another child stream.
